# ytb-dl-ui

基于 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 的本机桌面视频下载工具。Electron 内嵌页面，不监听 Web 端口。支持 YouTube、抖音、TikTok，平台实际可用性取决于 yt-dlp、登录权限与网络。

## 功能

- 浅色现代化界面：白色卡片、蓝色操作按钮、分状态任务标签和响应式布局。
- 单视频、批量分享链接、播放列表增量解析/跨页选择。
- 下载前解析真实源格式，逐视频选择“音视频下载后合并”、仅视频或仅音频；提供 MKV/MOV/MP4 合并容器，不重新编码。
- 默认嵌入平台章节，可手动关闭；人工/自动字幕可多选并内挂，同语言两种来源可同时保留，默认不下载字幕。
- 默认同时下载 3 个任务，可调整为 1–5；取消、重试、重启恢复。
- Chrome Cookie 导出教程、授权读取与本机缓存、到期/登录失效后刷新、监测导出的 cookies.txt 变化。
- 下载目录、默认系统代理及手动 HTTP/HTTPS/SOCKS 代理覆盖。
- yt-dlp stable 更新检查、用户确认后空闲安装、官方签名/SHA256 校验和回滚。

## 使用独立程序

目标产物为 macOS ARM64 / Intel 的 `.app`（ZIP 分发），Windows x64 / ARM64 的单文件 portable `.exe`。程序捆绑 Chromium、yt-dlp（包含 Python/EJS）、Node.js、FFmpeg 和 ffprobe；用户无需安装开发依赖。

1. 解压 macOS ZIP 后打开 `.app`，或双击 Windows `.exe`。自用版本不做付费签名/公证；只对你信任的构建按系统指引放行，不全局关闭系统安全功能。
2. 粘贴每行一个视频链接或分享文字，选择 Cookie 来源，点击“查看可用格式”，分别选择视频流与音频流，确认后才加入队列。
3. 播放列表使用“解析播放列表”，完成/停止后勾选条目，可跨页选择全部；点击“逐个选择条目格式”后，为每个视频单独确认。
4. 设置保存目录、并发。默认跟随系统代理；如需覆盖可填写手动代理。代理由你自行提供；程序不会让不可达的站点自动变得可达。
5. 完成后打开文件或所在目录。删除记录不删除下载文件。

Windows portable 会临时解压依赖再启动，首次打开可能较慢。数据保存在系统用户应用目录，不写回 EXE/.app；移动程序不丢失同一用户的历史，不是无痕便携模式。捆绑依赖使程序体积较大。

应用名称为 `ytb-dl-ui`，macOS 包内程序为 `ytb-dl-ui.app`，分发文件使用 `ytb-dl-ui-版本-平台-架构` 前缀。内部 npm 名称与应用标识保持不变，兼容原版本的数据目录和系统安全存储；已有下载目录设置也不会因更名被覆盖。

系统目标为 macOS 13+、Windows 10 22H2+/Windows 11。每种架构仍须在目标系统实测；配置了构建流水线不等于所有平台已完成验收。

## 下载前选择音视频编码

“查看可用格式”仅获取元数据，不下载媒体。列表来自当前视频的 yt-dlp 提取结果，使用已选择的 Cookie 来源和已保存代理；不同视频、账号和平台提供的格式可能不同。

- 显示格式 ID、容器、视频/音频编码、分辨率、帧率、码率、采样率、声道、语言、动态范围和文件大小；未知参数标注未知，估算大小标注“约”。列表可横向滚动，受 DRM 保护的流不提供选择。
- 可用“视频分辨率”下拉框筛选实际提供的尺寸（如 3840 × 2160 / 4K、1920 × 1080 / 1080p、1280 × 720 / 720p），再选择具体编码和音频。横屏与竖屏按真实宽高区分，未知分辨率单独列出；仅音频时不显示此控件。切换分辨率会清除不再匹配的视频选择，不改变音频、不自动降级或放大。每个视频重新选择。
- “音视频下载后合并”分别选择独立视频和独立音频，如 AV1 + Opus、H.264 + AAC，前提是平台对该视频实际提供。通过 FFmpeg 合并，容器可选 **MKV（默认）/ MOV / MP4**，复制原编码数据，不转码。容器不是编码；若 MOV/MP4 不兼容所选编码，明确报错并建议改选 MKV，不自动更换编码或降级。
- “最佳视频＋最佳音频”快捷按钮按 yt-dlp 已排序的格式列表选择最佳独立视频和最佳独立音频，不按文件大小判断。它会清除分辨率筛选、勾选对应流，仍需你确认才下载；也可以继续手动调整。最佳不代表源内容无损。
- 不再提供“音视频合一流”保存方式；平台只有合一流、没有独立流时明确提示不支持。也可仅保存独立视频/独立音频，单流保留源格式且不使用合并容器；仅视频没有声音，仅音频不是自动转成 MP3。旧版已经创建的合一流任务仍按原选项执行。
- “通常有损（编码推断）”是依据编码家族的提示，不是对具体编码模式的鉴定；无法判断时标注未知。FLAC、ALAC、PCM 等无损编码也不能证明上传前的母带无损。原样保存不增加转码损失，但不会恢复源文件已经丢失的信息。平台没有无损流时，不提供虚构的无损选项。
- 批量链接与播放列表逐个解析、逐个选择。每次确认只加入当前视频，其他视频仍需确认；可重试、跳过或结束选择。已确认的任务继续执行，未确认的视频不会下载。
- 精确格式 ID 保存在任务中，重试和重启续传沿用原选择。源格式下架、权限变化或 ID 失效时明确失败，不回退为其他编码；请重新解析并创建任务。

下载准备会分别显示“准备 Cookie 副本”“解析代理”“读取字幕信息”和“启动下载引擎 / 获取下载地址”，包含已等待秒数和阶段上限，不再统一显示为“同步 Cookie”。Cookie、字幕读取和引擎启动各最多等待 120 秒，代理解析最多 20 秒；阶段超时或取消会停止相关进程，不会继续在后台偷偷启动下载。引擎已发出媒体信息/进度后，正常下载不受启动阶段的 120 秒限制。

格式解析会显示 Cookie 同步、代理解析、平台格式读取三个阶段及已等待秒数。Cookie 同步和平台读取各最多等待 120 秒，代理解析最多 20 秒；超时会停止相关提取进程、清理 Cookie 临时副本并明确报错，允许重新解析或结束选择。Chrome 钥匙串授权弹窗未确认时请先处理；YouTube 提示登录/人机验证时，需要在浏览器完成后重新同步，程序不会绕过验证或静默禁用 Cookie。

新版入口不再使用“最佳画质 / MP4 / MP3”预设替用户自动选流。旧版已保存的任务仍按原选项执行（包括旧 MP3 转换任务），不会静默改变历史任务。

### 章节与内挂字幕

- 每个视频解析后显示平台提供的章节数量与标题。默认勾选“嵌入平台提供的章节信息”，可关闭；嵌入的是播放器可跳转的章节，不分割视频、不自动生成章节。仅音频也可嵌入章节，但须源容器支持。
- 字幕列表区分语言、人工/自动来源和可处理的文本格式（VTT/SRT/ASS/SSA），默认全部不选。支持多语言、同语言人工和自动字幕同时内挂；自动翻译字幕如由平台列在自动字幕中，也会显示。聊天回放、图片或其他不可处理格式不作为字幕提供。
- 字幕是播放器可切换的内挂轨道，不烧录进画面；仅音频模式不提供字幕选择。视频和音频仍复制源编码；MOV/MP4 内挂文本字幕时，字幕可能转换为 mov_text，样式可能简化，推荐 MKV。
- 下载时重新校验所选字幕来源；明确选择自动字幕时不会被同语言人工字幕替换。完整元数据仅在主进程内存及子进程管道传递，不向页面暴露字幕下载地址或请求头，不保存包含私密地址的元数据文件。
- 确认格式后，若视频、Cookie 副本身份和代理未变，且解析完成不足 **5 分钟**，直接复用刚才的字幕元数据，省去一次 yt-dlp 启动和重复的平台请求。只在主进程内存中保留，最多保留 5 个待启动任务的结果；排队过久、Cookie/代理变化、缓存淘汰、重试或重启后重新读取。复用并不保证平台签名链接永远有效；链接已失效时明确报错，需重新解析，不回退到其他编码。
- 完成前使用 ffprobe 验证所选字幕轨和平台章节实际存在。字幕失效、下载失败、容器不支持内挂或章节写入不完整时明确失败，不自动换容器，也不会仅留下外挂字幕却报告成功。请改选 MKV 后重新创建任务。章节/字幕选项随任务保存，重试和恢复沿用原选择。

## Cookie 与 Chrome

Cookie 是登录凭据，不要发给别人、上传网站或提交到 Git。程序仅将需要的站点 Cookie 存于本机私密目录，不向更新服务发送 Cookie，不写入日志。文件副本不是加密存储；代理凭据使用 Electron 系统安全存储。

### 导出文件

在设置中展开“如何从 Chrome 导出 Cookie？”：

1. 在 Chrome 登录目标站点。
2. 自行选择可信的本地 Cookie 导出扩展，核对来源、权限和隐私政策。程序不安装扩展、不推荐来历不明的扩展。
3. 导出当前站点为 **Netscape cookies.txt**，不使用 JSON。
4. 在程序中导入文件。如授权监测，重新导出到同一个路径后会自动加载。监测文件**不会让 Chrome 自动导出或刷新登录**。
5. 无效、半写入或被删除的文件会明确报错；旧副本不会被当成同步成功继续使用。重新导入可恢复。

### Chrome 自动同步

检测并选择 Chrome 配置文件（Default / Profile N），通过系统确认框授权。首次使用时调用 yt-dlp 读取 Chrome Cookie，过滤目标平台站点后保存为本机私密缓存；后续格式解析、播放列表解析和下载复用缓存，各操作使用独立副本，结束后清理副本，缓存可跨应用重启使用。

- 有到期时间的 Cookie 按实际到期时间判断；已过期条目不写入新缓存。含会话 Cookie（没有到期时间）时，最长缓存 **6 小时**。混合缓存以保留条目中最早的到期时间为准，不会因重复使用或重启而延长有效期。
- 兼容 Unix 秒和部分 yt-dlp Chrome 导出中保留的 Chromium 时间（1601 年起算的微秒）；后者先精确转换为 Unix 秒，再保存缓存和任务副本。不会把正常的 Chrome 时间戳当作无效到期时间，也不会因为单位不同而无限延长缓存。
- 网站可能提前撤销登录；遇到明确的 Cookie 失效或登录要求时，停用旧缓存、重新读取 Chrome 并重试一次。格式解析、播放列表、字幕元数据读取和下载统一遵循此规则。仍失败时提示在 Chrome 重新登录，不无限重试。
- 普通网络故障、限流、验证码/人机验证、年龄验证、私有视频或会员权限等不作为明确登录失效处理，不会因此自动读取 Chrome 或改为无 Cookie。
- 并发任务复用已刷新的缓存；基于同一旧缓存迟到的失败不会清除已刷新的新缓存。每个正在运行的任务仍使用自己的不可变副本。
- 设置中显示最近读取时间与缓存有效期；“立即刷新”始终重新读取 Chrome，不复用旧缓存。切换 Chrome 配置或撤销授权会清除缓存；刷新失败后不会偷偷继续使用已停用的旧缓存。
- 缓存位于本机应用数据的私密 Cookie 目录，文件权限为 `0600`、目录为 `0700`（Windows 还取决于用户目录 ACL），**不是加密存储**。不发送给更新服务，不向页面暴露 Cookie 内容；撤销授权会删除持久缓存，不影响此前已经取得副本的运行中任务。

- macOS 可能请求钥匙串访问；Windows Chrome 应用绑定加密、数据库锁定或其他浏览器保护可能阻止读取。程序不会提权或绕过保护，失败会引导手动导入。
- Cookie 过期时请在 Chrome **重新登录**，再同步或重新导出。程序不能代为登录、验证码处理或刷新服务端会话。
- Cookie 来源由你明确选择，不会把文件与 Chrome 数据静默混合。可删除文件/停止监测，或撤销 Chrome 授权。
- 正在运行的任务已取得的快照不随来源变化而改写；撤销后后续任务不能继续读取。

## 恢复与更新

### 系统代理

未设置手动代理时，通过 Electron 读取 macOS/Windows 当前系统代理规则（包括系统 PAC 的解析结果）；系统返回直连时显式直连，不偷偷使用终端代理环境变量。已有手动代理优先，删除手动代理并保存设置后恢复跟随系统；手动代理凭据仍使用系统安全存储。

格式解析、播放列表和每次媒体下载按入口视频/列表 URL 解析系统代理，并将选中的单个代理交给 yt-dlp。yt-dlp 的任务内部重定向和媒体 CDN 请求沿用该代理，不能逐个 CDN 执行 PAC；如系统 PAC 对网页与媒体 CDN 使用不同规则，请配置适合整项任务的手动代理。系统返回多个候选时使用第一个，不自动切到备用代理或直连；代理失败会明确报错。系统配置读取失败也不会悄悄直连。

引擎更新和更新资源的每个 HTTPS 重定向按目标 URL 分别解析代理。构建脚本不运行 Electron，仍使用 `HTTPS_PROXY` / `HTTP_PROXY`，不读取应用或系统代理设置。

下载任务与设置使用带版本的原子状态文件/备份存储。启动时自动恢复排队/中断任务，主动取消/失败的任务只能显式重试。保留原输出模板与 `.part` 文件，远端支持时续传；直播、过期链接、格式改变、合并/转码中断可能需要重新下载。成功任务须有非空最终文件，不能只根据进度 100% 判定。

启动检查 yt-dlp stable 更新不自动安装。确认后等待任务空闲，验证官方签名（固定公钥指纹）与哈希，在用户数据目录安装；保留上一版本供回滚，不改写应用包。离线或失败时明确报错并保留可用版本。完整应用、Node/FFmpeg 通过新的应用包更新。

更新元数据通过 GitHub JSON API 获取，签名与引擎文件按二进制下载。若旧版启动提示 HTTP 415，请使用新版应用包或重新构建；不是 Cookie 失效，无需重新导出 Cookie。设置中手动“检查更新”成功后，会清除本次启动的更新检查失败提示，不隐藏其他状态文件警告。

## 开发与构建

开发者需要 Node.js 22+、npm 和对应系统打包工具；这些不要求终端用户安装。

### 一键构建

仓库根目录提供 [macOS 脚本](build-mac.command) 和 [Windows 脚本](build-windows.cmd)。先安装 Node.js（推荐 22.23.4 或更新版本，包含 npm），首次构建需要联网；脚本不会安装 Node.js 或改变系统安全策略。

- **macOS**：双击 `build-mac.command`，或在终端执行 `./build-mac.command`。
- **Windows**：双击 `build-windows.cmd`，或在 CMD/PowerShell 执行 `.\build-windows.cmd`。窗口会保留构建结果，按任意键关闭。
- 默认构建当前 Node.js 的架构。可传 `x64`、`arm64` 或 `all`；`all` 构建该平台的两种架构：

```sh
# macOS
./build-mac.command all
```

```bat
REM Windows
.\build-windows.cmd all
```

脚本从任意工作目录运行都会定位到仓库根目录，依次执行 `npm ci`、下载/验证内置依赖、类型检查、编译、目标资源校验、平台打包及 SHA256 生成。任一步失败立即停止，不报告构建成功。代理通过 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量传入，不在脚本中写入凭据。

资源下载遇到超时、连接重置或临时 HTTP 错误时，每个资源最多尝试 3 次，打印失败资源名称；证书、永久 HTTP 错误与校验失败不会被绕过。若仍出现 `ETIMEDOUT`，请检查 GitHub、raw.githubusercontent.com、GitHub release-assets 和 nodejs.org 的可达性，或在启动脚本前设置代理。例如 macOS 使用 `HTTPS_PROXY=http://127.0.0.1:实际端口 ./build-mac.command`（将端口替换为你自己的本地 HTTP 代理端口）。应用内保存的代理不会自动用于构建脚本。

结果位于 `release/`；脚本只构建，不自动发布。指定其他架构时只校验其资源，不冒充原生运行验收。完整测试可单独执行 `npm test` 和 `npm run test:ui`。

### 手动构建

```sh
npm ci
npm run prepare:tools
npm run typecheck
npm test
npm run build
npm run test:ui
npm start
npm run package
npm run checksums
```

`prepare:tools` 下载固定版本资源并验证，首次需要访问 GitHub/Node.js；失败会退出，不能生成伪完整包。资源可以明确指定：

```sh
npm run prepare:tools -- mac arm64
npm run prepare:tools -- mac x64
npm run prepare:tools -- win x64
npm run prepare:tools -- win arm64
```

在匹配平台/架构的机器执行 `npm run package`，输出在 `release/`。macOS 进行 ad-hoc 签名；Windows portable 由 electron-builder 打包。不把系统 Homebrew 动态库当成独立分发资源。

macOS 开发机准备四种资源后可尝试 `npm run package:all` 交叉打包四份程序；交叉打包只验证文件完整性，不代替 Windows/Intel 干净机器的运行验收。自用 ad-hoc 签名包含 JIT 和 library-validation 兼容权限；公开分发应另行设计正式签名/公证。

可通过 `npm run smoke:package -- "/绝对路径/ytb-dl-ui.app/Contents/MacOS/ytb-dl-ui"` 检查打包后的应用启动。该检查使用隔离临时数据目录、禁用更新检查，不读取真实 Chrome Cookie；Windows 单文件程序仍应在 Windows 机器双击验证，不能把 macOS 的启动测试当作 Windows 验收。

需要隔离应用数据时，可用 `--user-data-dir=/已有目录的绝对路径` 启动；默认仍使用系统用户应用目录。
